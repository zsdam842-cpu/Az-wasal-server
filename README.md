# وصال | Wasal
## خادم تطبيق وصال للمراسلات الفورية

Wasal is a modern messaging application designed to provide fast,
secure, reliable, and user-friendly communication.

هذا المشروع مخصص لبناء خادم جديد لتطبيق وصال، مع بنية قابلة
للتطوير والتوسع، ودعم كامل لواجهات التطبيق العربية.

---

# 1. الهدف من المشروع

إنشاء خادم متكامل لتطبيق وصال يدعم:

- إنشاء الحسابات وتسجيل الدخول.
- إنشاء رمز وصال فريد لكل مستخدم.
- المحادثات الفردية والجماعية.
- إرسال الرسائل واستقبالها لحظيًا.
- إدارة جهات الاتصال.
- البحث عن المستخدمين.
- إرسال الصور ومقاطع الفيديو والملفات الصوتية.
- المكالمات الصوتية والمرئية.
- الإشعارات.
- حالات الرسائل.
- إدارة الخصوصية والإعدادات.
- دعم تطبيق Android أصلي.
- دعم اللغة العربية والاتجاه من اليمين إلى اليسار في التطبيق.
- قابلية التوسع مستقبلًا.

---

# 2. نظام رموز وصال

يجب أن يمتلك كل مستخدم رمز وصال فريدًا.

مواصفات الرمز:

- يتكون من 15 خانة بالضبط.
- يتكون من الحروف الإنجليزية الكبيرة والصغيرة والأرقام.
- يستخدم الأحرف A-Z وa-z والأرقام 0-9.
- لا يحتوي على مسافات.
- لا يحتوي على حروف عربية.
- لا يسمح باستخدام الرموز الخاصة.
- يجب أن يكون فريدًا لكل مستخدم.
- يُنشأ تلقائيًا عند إنشاء الحساب.
- لا يجوز تكرار الرمز بين المستخدمين.
- يُستخدم للبحث عن المستخدمين وإضافتهم.
- يظهر للمستخدم داخل صفحة الإعدادات.
- لا يُستخدم رقم الهاتف شرطًا لإنشاء الحساب.

الصيغة المعتمدة:

^[A-Za-z0-9]{15}$

يجب رفض أي رمز لا يطابق هذه الصيغة.

لا يُسمح بإنشاء رموز جديدة من خمسة أرقام.

يجب تطبيق التحقق من الرمز في الخادم وقاعدة البيانات والتطبيق.

---

# 3. الحسابات والمصادقة

يجب أن يدعم الخادم:

- إنشاء حساب جديد.
- تسجيل الدخول.
- تسجيل الخروج.
- التحقق من بيانات المستخدم.
- إصدار Access Token.
- إصدار Refresh Token.
- تحديث Access Token.
- إبطال جلسة المستخدم عند تسجيل الخروج.
- حماية واجهات API.
- إدارة الجلسات والأجهزة عند الحاجة.

متطلبات الأمان:

- لا يُطلب رقم هاتف إلزاميًا.
- لا يُطلب بريد إلكتروني إلزاميًا في التسجيل الأساسي.
- لا يُطلب رمز وصال من المستخدم عند إنشاء الحساب.
- يُنشأ رمز وصال تلقائيًا من الخادم.
- تُحفظ كلمات المرور باستخدام خوارزمية تجزئة آمنة.
- لا تُخزن كلمات المرور كنص صريح.
- لا تُرسل الرموز السرية إلى سجلات النظام.
- لا تُخزن مفاتيح JWT داخل مستودع GitHub العام.

مدة صلاحية الرموز المستهدفة:

- Access Token: 15 دقيقة.
- Refresh Token: 30 يومًا.

يجب التحقق من نوع الرمز، ومنع استخدام Refresh Token
بدلًا من Access Token للوصول إلى واجهات التطبيق المحمية.

يجب توفير واجهة لتحديث Access Token مع التحقق من
Refresh Token وإدارة الجلسات بصورة آمنة.
